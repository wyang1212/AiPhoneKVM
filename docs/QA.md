# AiPhoneKVM 2.9.4 验收记录

执行日期：2026-11-05 至 2026-11-06。主控与截图助手版本均为 **2.9.4 / versionCode 36**。真机范围为 M11 控制一台中兴手机；其他手机、游戏主机及其他设备未操作。本记录区分实际接收结果、隔离后端测试和示例界面截图。

## 本轮修复

- 更新目录同时识别 `-android.apk` 和历史 `-debug.apk`，排除截图助手等非主控文件。
- HTTP 配置提交与目标任务启动共用运行锁；请求体较慢、期间开始任务时，提交阶段再次检查并返回 409。
- 模型请求在同一锁内取得地址、模型名称和凭据快照，避免并发保存造成混用。
- 文本发送取消与离页等待结束，并向原目标释放输入；覆盖取消时仍有最后一次按下到达的情况。
- 相机观察面板关闭、停止和重新框选时清除旧冻结画面与四角草稿。
- 首页短横屏使用紧凑四列布局，所有八个模块可滚动访问，设备入口保持固定。系统自然横屏与应用请求方向分开处理，不强制修改用户旋转设置。
- 网站五秒轮询保留设备高级设置的展开状态，继续保留目标草稿、焦点和选区。
- 网站、模型、MQTT、更新源及助手提示地址使用保留的无效示例；公开包不包含开发者服务配置。
- 补充来源、修改说明、依赖许可证和应用内开源声明；提供经过扫描的独立源码导出工具。

## M11 → 中兴实际接收结果

- 保留数据升级两端至 code 36。主控保存的模型配置与首页排序保持；旧站点绑定原字段逐项保持，缺少的站点字段只在手机私有配置中迁移。助手临时测试配置在结束后按原字节恢复。
- 真实局域网截图与独立物理截屏均为 720×1600，首组平均像素误差约 1.13/255；不是只检查 JPEG 头。
- 蓝牙英文输入、Ctrl+A 替换、鼠标点击、重复命令去重、活动命令取消、排队输入取消均观察到目标事件。后续键盘事件显示 Ctrl/Shift 未卡住。
- **纯蓝牙精确落点没有全通过**：沿用既存灵敏度时，后续点击偏离输入框，浏览器保留了文档选区，最终文本值断言失败。此项不能写成精确坐标验收通过；需要对当前接收端重新校准。增强触屏与蓝牙相对鼠标是不同通道。
- 临时授权增强控制后，英文、中文/数字/符号/emoji 混合文本、光标追加及接收端写入核验通过，默认输入法未改变。真实触屏滑动使测试文档实际滚动。
- 竖屏、横屏、返回竖屏、180°、最终返回竖屏共五组，每组独立比较物理全帧、回传图、尺寸及旋转元数据，并在新画面找到测试色块、点击对应按钮、观察目标页面事件。五组通过，平均像素误差约 0.82–0.85/255；原旋转设置恢复。
- 保存的真实模型正确读出合成网页验证码，没有执行动作。首次在浏览器切换时取得黑帧，模型返回无法读取且未执行；画面稳定后正确识别。
- 真实模型目标循环完成两步测试：目标页面达到第 2 步，执行 2 个动作、观察 3 轮，看到新画面的完成标记后才结束。
- 慢请求体与任务启动并发时，配置接口返回 409，配置保持不变。运行任务期间拒绝手动输入，停止接口等待任务进入非活动取消状态；无令牌状态接口返回 401。
- 从实际手动键盘点击红色 F/J，目标原生输入记录均有正确按下和松开。FC 的 A/B、方向键及回中、Xbox 的 A、摇杆变化及回中已在目标原生事件确认。接收端浏览器的 Gamepad API 未暴露设备，因此未用它宣称游戏兼容。
- 媒体上下键的原生事件及 AudioService 的增大/减小请求均有实际记录。中兴被查询的音乐音量响应不对称，直接注入系统音量键也有同类表现；不将固定音量流数值变化算作全通过，不修改接收端音量策略。测试音量已恢复。

## 待验收与适用边界

- **真实无助手相机光学闭环本次按约定待验收**：需要固定摆放、完整拍摄目标屏幕、实际鼠标校准及操作后新相机帧。相机框选生命周期的界面回归通过，不能代替光学闭环。
- 语音真实识别与空鼠体感移动未作物理验收；示例页面不证明麦克风服务或传感器效果。
- 生产网站的 HTTPS/TLS、真实扫码绑定、跨公网连通、更新下载/安装流程没有在本轮完整执行。Portal 的 loopback MQTT 验收与手机的真实模型闭环分别记录。
- 系统权限窗、原生浏览器 prompt/confirm 的截图支持有限，截图清单列明缺口。界面图片使用无秘密的示例数据，不能当作实际服务器、模型或物理设备验收。
- 不推断其他 Android 厂商、电视、电脑、模拟器或游戏主机的兼容性。亮度、媒体键、手柄映射及纯蓝牙坐标需要接收端支持与校准。
