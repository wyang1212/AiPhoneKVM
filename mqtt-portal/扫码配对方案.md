# AiPhoneKVM 网站扫码绑定方案

实施状态：2026-10-28网站与主控端0.1.5.6/code13已实现。用户现场确认相机扫码绑定成功，最终独立APK的网页真实主页控制通过；图片选取返回链路未单独实机验收。历史方案主体保留，具体边界见配套《扫码绑定验收-0.1.5.6》。

## 完成标准

用户登录网站后，只需点击“添加主控端”，用手机AiPhoneKVM扫码并确认，即可把这台手机加入自己的账号，自动配置并验证MQTT。正常流程不填写设备ID、MQTT地址、用户名、密码、主题前缀或客户端ID。

网站绑定是“账号拥有这台主控手机”；主控手机与被控手机的蓝牙连接、被控端截图授权仍按现有流程操作。扫码不代替系统授权，不启动AI任务，也不自动跳进控制页。

## 正常操作

1. **网站：点击“添加主控端”。** 弹窗直接显示二维码、5分钟倒计时，以及“用AiPhoneKVM扫码连接”。无需先填名称。二维码过期可一键刷新，关闭弹窗取消本次请求。
2. **手机：点击“扫码绑定网站”。** 首页在原工具、模式和设备列表之外增加一行“网站连接”；未绑定显示扫码入口，已绑定显示网站账号与连接状态。保留现有首页布局与模式选择规则。
3. **手机：确认一次。** 展示可信站点、脱敏账号及当前手机名称，按钮“绑定并连接”。后台领取连接配置，自动保存，验证加密MQTT连接。默认名称来自手机型号，网站上可随时改名。
4. **网站：自动出现设备卡片。** 展示手机是否完成绑定、MQTT是否在线、是否已选择被控端。成功后关闭二维码弹窗，不再弹出一整页凭据。

同一台手机打开网站时，二维码下提供“在AiPhoneKVM中打开”，通过经过域名验证的HTTPS应用链接进入相同确认流程。未安装时显示主控端下载入口。扫码页支持从系统图片选择器读取二维码，作为相机不可用时的替代。

| 场景 | 展示与下一步 |

“已绑定”和“可远程控制”分别展示。不能仅因二维码被扫描、配置写入或服务器创建记录，就显示设备在线。后台配网验证不能打开AI任务或发送HID操作。

## 现有M11与重新绑定

- M11已按用户明确指定绑定到其网站账号；扫码方案沿用这条设备记录，不要求旧密码，不重复创建设备卡片。
- 已绑定同一账号：手机确认后更新连接配置；改名、蓝牙目标和其他本地设置保留。
- 已绑定其他账号：仅凭二维码或设备ID不能覆盖所有者。原账号先解除绑定，再由新账号扫码；账号丢失走独立恢复处理。
- 旧设备首次迁移由手机利用现有私有MQTT凭据证明身份，用户无需手动填写。无法证明已有设备身份时，不按型号或设备ID猜测归属。
- 绑定确认后生成该安装实例的私有设备凭证，用于后续身份确认；卸载清除数据后，可由原网站账号解除旧记录再添加。
- 有AI任务运行时，先提示停止任务并等待取消、松键完成，才允许更新配置。不自动恢复之前的AI目标。

## 配置交接与安全边界

- 二维码仅包含官方HTTPS绑定链接、协议版本和随机一次性令牌。令牌至少32字节随机数、5分钟有效、单次使用，服务端仅存摘要；网站账号密码、Cookie和MQTT密码均不放进二维码。
- 链接令牌放在URL片段，避免进入普通HTTP访问日志；手机通过HTTPS请求体兑换。扫码只接受允许的域名、路径和协议，不访问任意二维码网址或跟随跨域重定向。
- 手机确认页显示服务端返回的目标账号，不能直接相信二维码里的账号文案。取消或刷新立即撤销旧令牌。
- 创建和查看绑定请求要求网站登录，写操作校验CSRF；领取配置要求有效令牌和手机本次随机请求标识。服务端原子领取；同一请求断网重试可恢复，其他请求不能重复消费。
- 新设备首次领取配置后，先在本地安全保存，再验证MQTT并提交完成确认。服务器必须收到该设备对应的鉴权连通证明，网页才能显示成功。
- 现有设备改配使用临时凭据交接；新连接验证并确认保存后，才撤销旧凭据。超时撤销临时配置、恢复原设置，不提前删除可用连接。新旧凭据的交接窗口必须有限并可清理。
- 手机与网页控制端仍使用独立MQTT用户名、固定客户端ID和受限主题。手机不取得网站管理凭据，不能管理其他设备。
- 自动写入仅限MQTT绑定参数，不覆盖AI模型密钥、模型地址、蓝牙配置、截图配对码或本地HTTP控制口令。
- 选择无需Google服务的本地扫码组件，相机权限在点击扫码时申请；应用链接需要配套Android声明和站点签名验证文件。

## 实施范围与验收

| 步骤 | 交付与验收 |
| --- | --- |
| 网站与服务端 | 添加弹窗改成二维码；绑定请求、过期/取消、状态查询和凭据交接接口；两账号越权、重放、并发领取、断网恢复测试通过 |
| 主控端APK | 扫码/图片识别/同机应用链接、账号确认、自动保存和回滚；相机拒绝仍可继续；保留首页、模式选择和AI停止规则 |
| 实机联调 | 新设备零MQTT填写；M11原卡片迁移；Wi-Fi和移动数据均完成扫码绑定；断网重试不损坏原配置；网页状态与真实连接一致 |
| 发布交付 | 网站和主控端版本兼容校验；按发布时最新0.1.5.x递增，不能覆盖并行开发版本；APK及必要源码按项目规则上架并核验下载 |

首次验收还须观察一条网页到真实被控手机的无害操作，并明确是否具备蓝牙及必要授权。未完成实机验收不得写“扫码即可远程控制”。此方案现已实施；发布和实机验收边界以《扫码绑定验收-0.1.5.6》为准。

MQTT手动配置收进“高级设置”，保留诊断和独立客户端用途。此阶段不增加实时视频、云端AI任务或第三方账号登录。
